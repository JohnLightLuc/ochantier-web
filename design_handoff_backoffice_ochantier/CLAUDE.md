# O’CHANTIER ADMIN — notes projet

- Fichier principal : `Back Office OChantier.dc.html` (un seul Design Component). Composants partagés : Avatar, Button, StatCard, StateBlock, StatusBadge (.dc.html). Variables : `ochantier-tokens.css`.
- Versions figées dans `versions/` (Promoteurs V1, Tableau de bord V1, Paramètres V1, Ouvriers V1, Commerciaux V1, Chantiers V1). Ne jamais les modifier.
- Modules validés à ne pas modifier : Connexion, Tableau de bord, Promoteurs, Ouvriers, Commerciaux, Chantiers, Paramètres (écran d’origine `isParams` / `paramsVals`, route `#/parametres`).
- Architecture : routes par hash (`#/promoteurs/…`, `#/ouvriers/…` via `wroute`, `#/commerciaux/…` via `croute`, `#/chantiers/…` via `chroute`, `#/parametres`). `syncHash` gère le retour navigateur.
- Les sous-pages des modules Ouvriers / Commerciaux / Chantiers réutilisent le gabarit générique `isWorkerModule` + objet `wm` (en-tête, onglets, alertes, tuiles, panneaux, tableaux via `wTable`, calendrier, historique, formulaire en étapes `wm.form`).
- Listes : bloc générique `cfg = D.S[scr]` ; données dynamiques par module (`wRows`/`cRows`/`chRows`), filtres, tri, pagination (8/page), section du bas (`wBottom`/`cBottom`/`chBottom`).
- Modales : `openModal({ kind: 'fields' | 'reason' | 'doc' | 'leave', … })` ; actions avec chargement/succès/erreur via `wAct` / `cAct` ; toasts `toast(msg, { tone })`.
- Paramètres financiers X/Y/Z/R : `state.ps.saved` (défauts `PS0`).
- Données de démonstration : `this.P` (promoteurs), `this.W` (ouvriers), `this.C` (commerciaux), `this.CHS` (chantiers), `this.POOL` (offres OF, paiements PAY, avis AV, litiges LIT).
- Module « Besoins » (screen `besoins`, routes `#/besoins/…` via `broute`, formulaire `state.bform`). Besoin = recherche sans profils présélectionnés ; publication interne par métier dans `this.BOX.O` (réf. `BES-…/n`, pas appelée « offre » dans l’UI). Onglets : En attente d’ouvriers / Expirés (Actualiser) / Suspendus et clôturés (`BOTABS`) — les besoins entièrement couverts sortent de la liste. Affectation par besoin : `aff.st` À contacter → Contacté → Validé (ou Refusé, le poste redevient manquant). Couverture = ouvriers sélectionnés (non refusés) / recherchés. Étapes besoin couvert : Couvert · validation des ouvriers → Validé · acompte en attente (`b.paid`) → En attente de validation du promoteur (`b.proVal`) → Comblé. Suivi dans Affectations & Offres (`#/affectations/besoins/:id`, méthodes `ab*`, échéancier `abEch` avec X de Paramètres). Ajout manuel `boAddManual`, sélection Matching → `boAddAff`. Statuts dérivés par `boSync()`. Matching lit les postes ouverts non couverts (`boMatch`). Seuils : `BOR0` surchargé par `state.ps.saved.bo`.
- Offres des promoteurs (profils présélectionnés) : page « Affectations & Offres » (screen `affectations`, routes `#/affectations/offres/:id` via `aroute`), données `this.OFX`, méthodes `ofx*` (accepter/refuser par ouvrier, remplaçant similaire via `boPool` + `boScore`). Versions : `versions/Besoins & Offres V1 (avec validation).dc.html`, `versions/Back Office avant Besoins & Offres.dc.html`.

- Module « Matching » (screen `matching`, routes `#/matching/…` via `mroute`, méthodes `mx*`, données `this.MX` {cyc cycles, last dernier calcul par offre, sel sélections {main, repl, st}, rej, der dérogations, rc recalculs, notif, audit}). Moteur : `mxPool` (profils via `boPool`), `mxEval` (critères bloquants + 8 critères pondérés), `mxRes` (cache). Config `MXCFG0` surchargée par `state.ps.saved.mx`. Transmission → `boAddAff(o, p, 'Matching')` (propositions dans Affectations & Offres). Props démo : etatMatching, roleMatching, erreurMatching. Version avant module : `versions/O’CHANTIER ADMIN — Besoins V1 - Affections & Offres V1.dc.html`.
- Module « Pointages » (screen `pointages`, routes `#/pointages/…` via `proute`, méthodes `pt*`, données `this.PT` {R pointages par id, audit, notif, saved filtres}). Seed `ptSeed` (ouvriers validés de `this.W` × chantiers actifs de `this.CHS`), calculs `ptCalc` (statuts, durées, indicateurs, clôture), config `PTCFG0` surchargée par `state.ps.saved.pt`. Bloc haut `hasPtTop`/`ptTop` (liens, périodes, recherche, cartes cliquables). Simulation Application Promoteur `/pointages/application` (`ptApp`, `ptDo`, `ptGroup`, contrôles `ptCheck`). Prop démo : etatPointages. Version avant module : `versions/O’CHANTIER ADMIN — Matching V1/`.
- Module « Finance & Reporting » (screen `finance`, routes `#/finance-reporting/…` via `froute`, anciens `#/finance/…` acceptés). Agrège `this.PY` (Paiements) via `finRows` (`finFromOp` + `finMk`) + archives clôturées `this.FIN.A` ; `this.FIN` {A, months, closes (instantanés), audit, views, reports, res (écarts/doublons traités), sync}. Calculs `finAgg`, contexte `finCtx` (période `finPer`, base `fnBase`, filtres `fnF`, dictionnaire KPI `KD`), pages `finPg*` dispatchées par `finVals`. Config `FINCFG0` surchargée par `state.ps.saved.fin`. Rôles `FINROLE` (prop roleFinance), états (prop etatFinance). Version validée : `versions/O’CHANTIER ADMIN — Finance & Reporting V1/` (ne pas modifier). Taux Y/Z lus dans Paramètres (`finRates`, aussi utilisé par Paiements).
- Module « Paiements » (screen `paiements`, routes `#/paiements/…` via `yroute`, méthodes `py*`, données `this.PY` {O opérations, audit, notif, lots, saved}). Seed `pySeed` depuis les pointages clôturés (`this.PT`) + archives + acomptes. Calcul `pyCalc` (brut, bonus, indemnités, retenues, commission Y/Z via `finRates`, frais `PYCFG0.fees`, total promoteur, net ouvrier, commission nette, statut commission). Anomalies `pyAnoms`, checklist `pyChecks`, actions `pyValidate/pyPay/pyRev/pyLot/pyRefund/pyRec/pyCorr/pyItem`. Réutilise `hasPtTop`/`ptTop` et `ptPage`. Props démo : etatPaiements, rolePaiements.

- Module « Avis & Litiges » (screen `avis`, routes `#/avis-litiges/…` via `lroute`, méthodes `al*`, données `this.ALD` {PR prestations issues de `finRows`, AV avis, RC réclamations, LT litiges, notif, audit}). Seed `alSeed` (+ `alMkLit`), contexte `alCtx` (période `alPer`, filtres `alF`, KPI `K`), pages `alPg*` dispatchées par `alVals`. Note `alScore` (pondérations `ALCFG0.critO/critE`), inclusion `alIn`, SLA `alSla`, exposition `alExpo`, actions litige `alLtActs`. Demandes vers Paiements/Affectations/Pointages stockées dans le litige (`fin`, `rempl`, `ptc`), jamais exécutées directement. Config `ALCFG0` surchargée par `state.ps.saved.al`. Props démo : etatAvis, roleAvis.

- Paramètres : écran d’origine conservé (catégorie « Commissions & frais » = `paramsVals0`, inchangé). Sous-pages des autres catégories (`PSCATS`, `ps.cat`, routes `#/parametres/<cat>`) rendues dans le même gabarit via `psSubDefs`/`psSubVals` (brouillon `ps.sd`, enregistrement `psSubSave`, journal `ps.log`, valeurs libres dans `ps.saved.stg`, valeurs liées aux modules via `psGetB`/`psPutB` sur `ps.saved.pt|mx|py|…`). Code étendu `st*`/`stVals` non routé (seules ses données `stSeed` : utilisateurs, intégrations, sont réutilisées).

- Module « Landing Page » (screen `landing`, après Paramètres dans le menu, routes `#/landing-page[/contenu/:section|/candidatures[/:id]|/messages[/:id]|/publications]` via `lpRoute`, méthodes `lp*`, données `this.LPD` {pub version en ligne, draft brouillon auto, vers historique avec instantanés, cand candidatures « Devenir ouvrier », msg messages de contact}). Contenu calqué sur `Landing OChantier v2.dc.html` (projet 94d23de8…) : sections `LPSEC` (dont Newsletter, ajoutée au back-office), champs `lpDefs`, validation `lpErr`, contrôles `lpChecks` (erreurs bloquent `lpPublish`), diff `lpChanges`. Tarifs lus depuis `ABOPL` (Abonnements), carte depuis `this.CHS`. Candidature → profil ouvrier via `lpConvert` (`mkWorker`). Prop démo : roleLanding. Version avant module : `versions/Back Office avant Landing Page.dc.html`.
- Module « Abonnements » (screen `abonnements`, routes `#/abonnements` et `#/abonnements/:id` via `aboroute`, méthodes `abo*`, données `this.ABO` seedées depuis `this.P`). Formules `ABOPL` (Solo gratuit 1 utilisateur, Équipe 15 000 FCFA/5, Pro 35 000 FCFA/15), rôles `ABOROLES`. Ajout/modification `aboPlanForm`, suppression `aboDelPlan` (Solo non supprimable ; abonnés migrés vers une formule choisie, capacité vérifiée). Onglets Abonnés / Formules ; fiche : carte formule, changement de formule (montée immédiate au prorata, descente programmée `pending`), utilisateurs (invitation SMS/e-mail, retrait), statut (Actif, Essai, Impayé, Suspendu, Résilié), factures, historique. Version avant module : `versions/Back Office avant Abonnements.dc.html`.

- Modules O’CHANTIER PRO (d’après « Documentation O’CHANTIER PRO.pdf ») : menu après Chantiers — « Entrepreneurs / Techniciens » (screen `pros`, `#/entrepreneurs[/:id]`), « Demandes de devis » (screen `ddevis`, `#/demandes-devis[/:id]`), « Offres contractuelles » (screen `ocontrats`, `#/offres-contractuelles[/:id]`). Routage `prRoute`/`prOpen` (table `PRROUTE`), méthodes `pr*`, données `this.PRD` {E professionnels KYB/KYC, DV demandes, OC offres, audit} seedées par `prData`. Statuts dérivés `prDvSt`/`prOcSt`. Gabarit générique `isPro`/`pro` (liste + fiche) ; sections de fiche via le composant enfant `ProSection.dc.html` (normalisées par `prSec`). Commission de service (sans lettre « R » dans l’UI) propre à chaque type d’opportunité (`rDv` demandes de devis, `rOc` offres contractuelles, défaut 10 % chacun, `PROCFG0`, `prRate(scr)`, surchargée par `state.ps.saved.pro` via `prRules` ; distincte du « Seuil R » de Paramètres) : ajoutée à chaque offre du professionnel (total promoteur = montant pro + R), taux figé sur l’offre (`r`), collectée à chaque encaissement (visite, acompte) et reversée à O’CHANTIER (`prLedger`, `prReverse`, onglet « Commissions R »). Acompte d’attribution lu dans Paramètres (X, `ps.saved.x`), plus de champ dans les Règles. Actions promoteur simulées (« Simulation · … »). Pièces KYB/KYC : visionneuse `state.prDoc` / `prDocView` (aperçu, zoom, rotation, navigation) avec Confirmer `prDocOk`, Demander un complément `prDocAsk` (statut « Complément demandé »), Rejeter `prDocReject`. Devis accepté ≠ attribution : statut « Devis accepté » → le promoteur publie une offre contractuelle liée (`prOcFromDv`, `d.ocId` / `o.dvId`, `o.prioId`) ouverte à tous, l’auteur du devis prioritaire (notifié en premier, en tête des réponses, badge « Prioritaire »), le promoteur peut retenir un autre pro. Plus d’acompte côté demande de devis (acompte et attribution uniquement via l’offre contractuelle). Version avant modules : `versions/Back Office avant Entrepreneurs-Devis-Offres.dc.html`.
